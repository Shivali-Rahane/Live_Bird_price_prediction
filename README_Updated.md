# Live Bird Price Prediction Dashboard

A Streamlit prototype for exploring live-bird price trends, generating a seven-day price forecast, and displaying an indicative harvest-window suggestion.

> **Important:** The included dataset is synthetic and is generated by `src/generate_data.py`. Forecast metrics and dashboard outputs are demonstrations of the workflow, not real market forecasts or validated commercial advice.

Open Command Prompt or PowerShell in the project folder and run:

```bash

.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python train.py
streamlit run app.py
```

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python train.py
```

The training command generates the synthetic dataset if it is absent, prepares the data, trains/evaluates the model, and saves the outputs configured by the project. The Streamlit command starts the dashboard; follow the local URL shown in the terminal (normally `http://localhost:8501`).

If a command fails, check that the virtual environment is activated and that the installed Python version is compatible with `requirements.txt`.

## 4. Dataset

The prototype uses **synthetic daily data** for five Maharashtra districts covering November 2023 to October 2026. The generator simulates seasonality, feed-cost effects, noise, and a Sunday uplift, and includes data-quality issues such as missing values, duplicate records, gaps, and outliers.

The synthetic data is intended to demonstrate data preparation and modelling. It is not collected from live markets and must not be interpreted as actual bird prices.

To regenerate the dataset, run:

```bash
python train.py
```

To use a real dataset, the training script is documented to accept a CSV with these columns:

```text
date, district, live_bird_price, season, flock_age_days, feed_cost_index
```

Example command:

```bash
python train.py path/to/your_data.csv
```

Use real data only when you have permission to use it, and verify its units, coverage, and quality before interpreting the results.

## 5. Data preparation

The pipeline is designed to:

- Parse dates and convert numeric fields to numeric types.
- Remove duplicate district-date records.
- Reindex district series to a complete daily calendar.
- Interpolate short price/feed-index gaps within the observed history.
- Flag extreme values using a robust rolling-median-based rule and handle flagged values as described in the cleaning code.
- Save a cleaning report, where configured, so that data-quality decisions can be inspected.

The synthetic generator injects some data-quality issues to demonstrate these steps. In a real deployment, flagged outliers should be reviewed against market information because genuine events can also cause abrupt price changes. Review the actual cleaning report and implementation when running the project.

## 6. Feature engineering and modelling

The documented feature pipeline uses historical price lags, rolling statistics, short-term momentum, feed-index information, calendar features, and district information to predict the next day's price. Features should use only information available at the forecast origin to avoid look-ahead leakage.

The model comparison includes:

- **Naive baseline:** carries the latest observed price forward.
- **Seasonal-naive baseline:** uses the price from the same weekday in the previous week.
- **Random Forest:** a one-step model applied recursively to generate forecasts up to seven days ahead.

For multi-day forecasts, the documented approach holds the feed-cost index constant. Recursive forecasts can accumulate error as the horizon increases.

## 7. Model evaluation

The original project results recorded in this README are:

| Model | MAE (₹/kg) | RMSE (₹/kg) | MAPE |
|---|---:|---:|---:|
| Naive (last price) | 1.71 | 2.28 | 2.09% |
| Seasonal naive (7-day) | 2.06 | 2.69 | 2.52% |
| Random Forest | 1.64 | 2.15 | 2.02% |

The original evaluation notes describe a time-aware test window of 3 August 2026 to 31 October 2026 and rolling-origin seven-day backtesting. **Re-run `python train.py` and confirm these figures against the generated evaluation output before submission.** Do not report these values as independently verified if the run does not reproduce them.

- **MAE:** average absolute prediction error, expressed here in ₹/kg.
- **RMSE:** root mean squared error; it gives more weight to larger errors.
- **MAPE:** mean absolute percentage error.

On the synthetic data, the recorded Random Forest result is only marginally better than the naive baseline. This does not establish that the model will perform similarly on real market data, and statistical significance has not been established.

## 9. Harvest-window logic and assumptions

The project includes a rule-based harvest-window suggestion based on flock age and forecast movement. The configured thresholds are illustrative placeholders, not validated agricultural recommendations. The suggestion is decision support only and is not a substitute for farm, veterinary, market, or business guidance.

The forecast holds the feed-cost index constant. The prototype does not model all real-world drivers, including weather, demand, disease, festivals, policy changes, supply conditions, or regional trade flows.

## 10. Limitations

- The data is synthetic, so the learned patterns reflect assumptions built into the generator.
- Real market prices can be affected by shocks and drivers not represented in the prototype.
- Recursive forecasting may accumulate error across the seven-day horizon.
- The test window covers a limited period and does not establish performance across multiple market cycles.
- The forecast uncertainty band is approximate and may not be calibrated.
- The harvest rule does not account for every farm-specific factor, such as body weight, mortality, feed conversion ratio, contracts, or logistics.
- Performance on real market data has not been established by the synthetic-data results.
